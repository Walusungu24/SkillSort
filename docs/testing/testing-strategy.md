# Testing Strategy

This document outlines the testing approach for SkillsSort.

## Current approach

- **Synthetic test data only** — All tests use fictional CVs generated by
  `scripts/generate_synthetic_cvs.py`. No real applicant data is committed.
- **POC extraction testing** — The extraction POC (`scripts/poc_extractor.py`)
  processes all synthetic CVs and reports per-field results. See
  `docs/architecture/extraction_accuracy_notes.md` for current accuracy.

## Test set

| File | Scenario | Tests |
|------|----------|------|
| cv1_complete | All fields present | Full extraction accuracy |
| cv2_missing_fields | No phone, no certifications | Missing field handling |
| cv3_overlapping_dates | Overlapping employment | Overlap detection + uncertain flag |
| cv4_minimal | Only name + email | Partial extraction + status |
| cv5_unstructured | No headers, abbreviations | Robustness to unstructured input |
| cv6_rich_experience | Many roles, 12 skills | Large input handling |
| cv7_corrupt | Invalid file type | Failure handling |

Each CV exists in both PDF and DOCX format (12 valid files + 1 invalid).

## Planned improvements

1. **Unit tests (Phase 3)** — Wrap extraction functions in pytest cases for
   automated regression testing.
2. **Gold standard annotations** — Manually label expected values for each
   synthetic CV so accuracy can be verified automatically.
3. **Integration tests (Phase 3)** — Test the full upload-to-results workflow
   through Django's test client.
4. **Expanded test set** — Add CVs with two-column layouts, photos, non-standard
   fonts, and multilingual content.
